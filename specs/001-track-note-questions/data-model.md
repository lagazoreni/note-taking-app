# Data Model: Interactive Note Questions

**Date**: 2026-08-09  
**Database**: SQLite  
**Canonical time format**: UTC RFC 3339 text with fractional seconds  
**Canonical identifier**: lowercase UUID text

## Modeling conventions

- All mutable top-level entities use `id`, `created_at`, `updated_at`, and integer `version` fields.
- IDs are generated by the Go service from cryptographically secure randomness and never reused.
- `version` starts at 1 and increments on every successful user-visible mutation.
- SQLite foreign keys are enabled on every connection. Parent records with dependent user content use restrictive deletion unless an explicit service transaction resolves the dependents.
- Enumerations use lowercase storage values and database `CHECK` constraints.
- Empty user text is trimmed and stored as `NULL` when optional. Required text must remain non-empty after trimming.
- Service validation complements database constraints for cross-table rules that SQLite cannot express safely in a simple constraint.
- MVP deletions are hard deletions after required review. Tombstones and revision history are deferred with cross-device synchronization.

## Relationship overview

```text
Workspace 1 ── * Topic
Workspace 1 ── * Note
Workspace 1 ── * Question
Workspace 1 ── * Tag (owner)

Note 0..1 ── * Note (parent/children)
Topic 0..1 ── * Note
Note * ── * Question       through NoteQuestion
Note * ── * Tag            through NoteTag
Question * ── * Tag        through QuestionTag
Question 1 ── 0..1 Reminder
Tag * ── * Workspace       through TagWorkspaceAccess
```

## Entities

### Workspace

Represents a separate user context such as Work, Personal, or Studies.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `id` | UUID text | yes | Primary key |
| `name` | text | yes | Trimmed, 1–100 characters; case-insensitively unique |
| `created_at` | timestamp text | yes | Set on creation |
| `updated_at` | timestamp text | yes | Not before `created_at` |
| `version` | integer | yes | Starts at 1; positive |

**Deletion**: A non-empty workspace cannot be deleted without a separate reviewed cascade operation. MVP may initially expose deletion only for empty workspaces.

### Topic

A workspace-owned category directly assigned to notes.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `id` | UUID text | yes | Primary key |
| `workspace_id` | UUID text | yes | References `workspaces`; restrictive delete |
| `name` | text | yes | Trimmed, 1–100 characters; case-insensitively unique within workspace |
| `created_at` | timestamp text | yes | Set on creation |
| `updated_at` | timestamp text | yes | Not before `created_at` |
| `version` | integer | yes | Starts at 1; positive |

**Deletion**: Deleting a topic sets linked notes’ `topic_id` to `NULL` in one transaction after confirmation; it never deletes notes.

### Note

Canonical user-authored note content and hierarchy metadata.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `id` | UUID text | yes | Primary key |
| `workspace_id` | UUID text | yes | References `workspaces`; immutable in the MVP |
| `topic_id` | UUID text | no | References a topic in the same workspace; set null on topic deletion |
| `parent_note_id` | UUID text | no | References another note in the same workspace; cannot reference self or a descendant |
| `title` | text | yes | Trimmed, 1–300 characters |
| `body_markdown` | text | yes | May be empty; max accepted request size documented by API; valid question directives only |
| `created_at` | timestamp text | yes | Set on creation |
| `updated_at` | timestamp text | yes | Changes with title, body, topic, parent, or link presentation |
| `version` | integer | yes | Optimistic concurrency token |

**Hierarchy rules**:

1. Parent and child belong to the same workspace.
2. A note cannot parent itself.
3. Before assigning a parent, walk ancestors in the same transaction and reject any cycle.
4. Deleting a parent requires an explicit decision to re-parent each direct child to the deleted note’s parent, make it a root, or delete it through its own reviewed operation.

**Content/link rule**: Every `{{question:<id>}}` directive has exactly one matching `note_questions` row for this note. A linked question may be represented at most once in one note body. Links displayed outside the exact body position may exist only if the contract explicitly marks them as detached; MVP does not create detached links.

### Question

The single canonical form of a question shared among linked notes and central views.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `id` | UUID text | yes | Primary key |
| `workspace_id` | UUID text | yes | References `workspaces`; immutable in the MVP; all linked notes must share it |
| `question_text` | text | yes | Trimmed, 1–10,000 characters |
| `answer_markdown` | text | no | `NULL` when empty after trimming |
| `status` | enum text | yes | `unanswered`, `in_progress`, `deferred`, `answered` |
| `priority` | enum text | yes | `none`, `low`, `medium`, `high`, `urgent`; default `none` |
| `due_date` | date text | no | Local calendar date `YYYY-MM-DD` |
| `created_at` | timestamp text | yes | Set on creation |
| `updated_at` | timestamp text | yes | Changes for content, lifecycle, date, priority, tags, or links |
| `version` | integer | yes | Optimistic concurrency token |

**Database constraints**:

- `status = 'answered'` requires `answer_markdown` to be non-null and non-empty after trimming.
- Removing an answer and changing away from `answered` occur in the same transaction.

**Lifecycle transitions**:

| From | To | Allowed when | Result |
|---|---|---|---|
| New | `unanswered` | Always | Default creation state |
| Any active status | Any active status | Valid request/version | Preserve answer and links |
| Any active status | `answered` | Non-empty answer exists in resulting record | Preserve all links; appears in Answered view |
| `answered` | `in_progress` | Always | Default reopen; preserve answer |
| `answered` | `unanswered` or `deferred` | Explicit choice | Preserve answer unless explicitly edited |
| `answered` | `answered` with empty answer | Never | Reject validation |

“Active” means any status except `answered`.

### NoteQuestion

Many-to-many link and per-note presentation for a shared question.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `note_id` | UUID text | yes | References `notes`; cascade only inside reviewed note deletion transaction |
| `question_id` | UUID text | yes | References `questions`; restrictive delete unless explicit question deletion |
| `display_mode` | enum text | yes | `expanded`, `collapsed`, `link`; default `collapsed` |
| `position` | integer | yes | Zero-based directive order in note; non-negative |
| `created_at` | timestamp text | yes | Set when linked |
| `updated_at` | timestamp text | yes | Changes with presentation/position |

**Key and constraints**:

- Composite primary key: (`note_id`, `question_id`).
- Unique (`note_id`, `position`).
- Note and question must have the same `workspace_id`; enforced by service transaction and integration tests.
- Creating/removing/reordering links and updating `body_markdown` occur atomically.

### Tag

A flexible label owned by one workspace and optionally made available to others.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `id` | UUID text | yes | Primary key |
| `owner_workspace_id` | UUID text | yes | References `workspaces` |
| `name` | text | yes | Trimmed, 1–100 characters; case-insensitively unique per owner |
| `created_at` | timestamp text | yes | Set on creation |
| `updated_at` | timestamp text | yes | Changes with name or access |
| `version` | integer | yes | Optimistic concurrency token |

A tag is always available in its owner workspace. Access elsewhere requires a `tag_workspace_access` row.

### TagWorkspaceAccess

Explicitly shares a tag into another workspace.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `tag_id` | UUID text | yes | References `tags`; cascade on tag deletion |
| `workspace_id` | UUID text | yes | References `workspaces`; cascade on workspace deletion only after reviewed workspace deletion |
| `created_at` | timestamp text | yes | Audit metadata |

**Key**: (`tag_id`, `workspace_id`). The owner workspace is implicit and must not have a redundant row.

**Unsharing rule**: If content in the target workspace already uses the tag, preview the affected uses. User must confirm either removal from that content or cancellation; inaccessible retained assignments are not permitted.

### NoteTag

| Field | Type | Required | Rules |
|---|---|---:|---|
| `note_id` | UUID text | yes | References `notes`; cascade on reviewed note deletion |
| `tag_id` | UUID text | yes | References `tags`; cascade on tag deletion |
| `created_at` | timestamp text | yes | Set on assignment |

**Key**: (`note_id`, `tag_id`). Tag must be owned by or explicitly available to the note workspace.

### QuestionTag

| Field | Type | Required | Rules |
|---|---|---:|---|
| `question_id` | UUID text | yes | References `questions`; cascade on explicit question deletion |
| `tag_id` | UUID text | yes | References `tags`; cascade on tag deletion |
| `created_at` | timestamp text | yes | Set on assignment |

**Key**: (`question_id`, `tag_id`). Tag must be owned by or explicitly available to the question workspace.

### Reminder

At most one scheduled reminder for a question in MVP.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `id` | UUID text | yes | Primary key |
| `question_id` | UUID text | yes | Unique; references `questions`; cascade on explicit question deletion |
| `scheduled_at` | timestamp text | yes | UTC instant |
| `state` | enum text | yes | `pending`, `delivered`, `missed`, `dismissed` |
| `last_evaluated_at` | timestamp text | no | Last browser/backend reminder check |
| `created_at` | timestamp text | yes | Set on creation |
| `updated_at` | timestamp text | yes | Changes on schedule/state updates |
| `version` | integer | yes | Optimistic concurrency token |

**State transitions**:

- New or rescheduled reminder → `pending`.
- Pending and displayed at/after schedule → `delivered`.
- Pending and found after its useful alert window → `missed`.
- Delivered or missed → `dismissed` by user.
- Any state → `pending` when explicitly rescheduled.

Reminder completion does not automatically answer or change the linked question.

### ImportSession

Tracks a validated, staged import without modifying canonical data.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `id` | UUID text | yes | Primary key |
| `archive_path` | text | yes | Must resolve beneath configured import staging directory; never returned to client |
| `archive_sha256` | text | yes | Lowercase 64-character digest |
| `format_version` | integer | yes | Supported export contract version |
| `state` | enum text | yes | `validated`, `applied`, `cancelled`, `expired` |
| `conflict_count` | integer | yes | Non-negative |
| `created_at` | timestamp text | yes | Set after staging |
| `expires_at` | timestamp text | yes | Default 24 hours after creation |
| `applied_at` | timestamp text | no | Set after successful commit |

Conflicts are stored in normalized `import_conflicts` records or in a validated staging document referenced by this session. The apply transaction rechecks archive digest, expiry, state, and current target versions before any mutation.

### ImportConflict

| Field | Type | Required | Rules |
|---|---|---:|---|
| `import_session_id` | UUID text | yes | References `import_sessions`; cascade when staging is purged |
| `conflict_id` | UUID text | yes | Stable within session |
| `entity_type` | enum text | yes | One of the exported entity types |
| `entity_id` | UUID text | yes | Conflicting canonical ID |
| `reason` | enum text | yes | `different_content`, `missing_dependency`, `name_collision`, `newer_existing` |
| `existing_version` | integer | no | Current version if record exists |
| `imported_version` | integer | no | Archive version if present |

**Key**: (`import_session_id`, `conflict_id`). User resolution (`keep_existing` or `use_imported`) is supplied to apply and validated for every resolvable conflict.

### SchemaMigration

| Field | Type | Required | Rules |
|---|---|---:|---|
| `version` | integer | yes | Primary key; strictly increasing |
| `name` | text | yes | Migration description |
| `checksum` | text | yes | Detect changed released migrations |
| `applied_at` | timestamp text | yes | Completion time |

Startup fails readiness if an applied migration checksum differs or a migration cannot commit.

## Full-text search

### `notes_fts`

FTS5 external-content index over:

- `note_id` (unindexed identity)
- `workspace_id` (unindexed filter aid)
- `title`
- `body_markdown` with question directives omitted from indexed visible text

### `questions_fts`

FTS5 external-content index over:

- `question_id` (unindexed identity)
- `workspace_id` (unindexed filter aid)
- `question_text`
- `answer_markdown`

Insert/update/delete triggers keep each index consistent inside the same write transaction. A migration provides a rebuild operation, and integrity tests compare indexed record counts and sampled queries to canonical tables.

Search returns entity type, entity ID, workspace, escaped snippet, rank, and navigation destination. Authorization is absent in MVP, but workspace scope remains mandatory in query construction unless “all workspaces” is explicitly selected. A question matches a topic filter when an `EXISTS` relation finds at least one linked note assigned to the selected topic; multiple matching linked notes must not duplicate the question result.

## Required indexes

Beyond primary and unique keys:

- `notes(workspace_id, parent_note_id, title, id)`
- `notes(workspace_id, topic_id, updated_at, id)`
- `questions(workspace_id, status, updated_at, id)`
- `questions(workspace_id, due_date, priority, id)`
- `questions(workspace_id, created_at, id)`
- `note_questions(question_id, note_id)`
- `note_questions(note_id, position)`
- `note_tags(tag_id, note_id)` and `question_tags(tag_id, question_id)`
- `tag_workspace_access(workspace_id, tag_id)`
- `reminders(state, scheduled_at, id)`
- `import_sessions(state, expires_at)`

Query-plan integration tests must prove representative filter/sort queries do not perform unintended full scans at the specified data scale.

## Aggregate transaction boundaries

1. **Save note**: validate version/hierarchy/directives; update note; insert/update/delete note-question links; bump affected question update metadata if link visibility changes; commit.
2. **Save question**: validate status/answer/workspace/tags; update question and tags/reminder as requested; update FTS; commit.
3. **Delete note**: validate preview token and versions; resolve children; unlink multiply linked questions; keep or delete singly linked questions per decisions; delete note; commit.
4. **Share/unshare tag**: validate affected assignments and decisions; change access and assignments; commit.
5. **Apply import**: revalidate session/conflicts; apply all selected entities and relationships in dependency order; rebuild/check FTS as needed; mark session applied; commit.

Cross-workspace note and question moves are outside the MVP; attempts are rejected before mutation.

## Export mapping

The export format serializes canonical entities and relationships, excluding operational-only fields:

- Included: workspaces, topics, notes, questions, note-question links, tags, tag access, note tags, question tags, reminders, versions, and timestamps.
- Excluded: migration rows, FTS tables, absolute archive paths, request logs, temporary import sessions/conflicts, and derived search snippets.
- FTS indexes are rebuilt from imported canonical content.
- Export order is deterministic by entity type then ID so checksums and comparisons are repeatable.
